# 职位统计工具（job-stats）

多平台职位采集 + 本地统计分析。覆盖 **Boss直聘 / 前程无忧 / 智通直聘**。

## ⚠️ 合规使用须知（先读这个）

- 本工具**只采集公开职位信息**（职位名/薪资/公司/城市/技能标签），**不采集**任何简历、联系方式等个人信息
- 内置限速：每次翻页随机间隔 3~8 秒；每日采集总量熔断 200 条（`jobstats/config.py` 中可查）
- 职位正文（JD）要逐条打开详情页，额度单独算且更小：**每天 20 条**（`DETAIL_DAILY_CAP`）
- 投递状态/备注（`status`/`note`）是**你在这台机器上自己标的**，不来自平台，也不会拿你的
  登录状态去平台查"HR 有没有已读"这类私域数据
- 数据**只存你本地** SQLite，不上传、不分发；请勿用于商业再分发
- 如遇平台验证码/风控提示，**立即停止**，隔天再试。请勿调高频率、请勿多开

## 安装

**只需要双击 `install.bat`**（安装逻辑在 `install.py`，批处理只负责找到 Python 并启动它）。
它会检查 Python 版本 → 在项目里建一个独立的 `.venv` → 装 playwright → 下载采集用的
浏览器内核 → 最后跑一遍离线自检测试（不联网、不采集）。装完以后不用再碰它，中途网络断了
就重新双击一次，已完成的步骤会自动跳过。

手工装（不用 `.venv`，直接系统 Python）等价于：

```bash
pip install -r requirements.txt
playwright install chromium
```

### 拷给别人跑（Windows）

把项目文件夹整个拷过去（或压缩发过去），对方只需要两步：

1. 装 Python 3.10 或更高（代码用了 `str | None` 这类新语法，3.9 导入就报错），
   官网安装页面 `https://www.python.org/downloads/`，安装时勾选 *Add python.exe to PATH*
2. 双击 `install.bat`，跑完再双击 `start.bat`

依赖只有一个 `playwright`，数据库用 Python 自带的 SQLite，都不用另装。
Boss 那家用的是对方自己电脑上的 Edge，不需要下载；智通直聘纯 HTTP，连浏览器都不开。

**别把 `data/` 拷给别人**：里面是 `jobs.db`（你的采集记录，含职位正文和你打的标记），
写了匹配度之后还有 `profile.txt`——那是你的技能和学历、期望薪资，比职位数据更该留在本机。
要给的只有代码：`cli.py`、`install.bat`、`install.py`、`start.bat`、`login-boss.bat`、`README.md`、
`requirements.txt`、`jobstats/`、`tests/`（`login-check.bat` 是接影刀那套巡检用的，对方用不上，给不给都行）。
对方首次运行会自己生成空库。`reports/` 是生成产物，也不用给。

登录态和 Boss 那份浏览器配置都在项目外（`%LOCALAPPDATA%\job-stats\auth` 和 `edge-profile`，
两处都等于你的账号 cookie），本来就不跟着文件夹走——所以整包压缩发人是安全的。
对方要采 Boss，让他自己双击 `login-boss.bat` 扫一次码。

`.venv` 是**按机器**生成的（里面写死了绝对路径），换机器就删掉它重新双击 `install.bat`；
浏览器内核默认装在 `%LOCALAPPDATA%\ms-playwright`，同一台机器上多个副本共用一份，不会重复下载。

## 使用

**日常只用一条命令**：双击 `start.bat`，或

```bash
python cli.py serve
```

浏览器会自动打开 `http://127.0.0.1:8765`，**采集和筛选都在这个页面里完成**
（选平台/城市/关键词 → 开始采集 → 完成后表格自动刷新）。Ctrl+C 停止。

页面里那个采集任务的滚动日志**同时按天落一份文件**：`data\logs\collect-2026-10-13.log`，
每行是 `时:分:秒 [平台] 任务id 内容`（日期在文件名里）。关页面、重启 `serve` 都翻得回来——
原来那份日志只在内存里，窗口一关就没法判断"上午那次到底跑了几页"。
一次任务从 `开始：…` 到 `完成：采到 X 条，入库新增 Y 条`（或 `[失败] …`）都在里面。
按天一个文件、没有轮转，嫌大了直接删，跟 `data\jobs.db` 没关系。
失败那行只写报错的**第一行**，不带 `Call log`——那玩意儿会把请求头连同 `bst`/`zp_at` 一起原样打出来。

服务自己也有一份启停留痕：`data\logs\serve-2026-10-24.log`，每行 `时:分:秒 内容`（日期同样在文件名里）。
2026-10-24 23:02 我在 8791 上实测的两行：

```
23:02:55 启动：监听 127.0.0.1:8791 pid 6500，令牌随机（外部程序连不上），今日入库 30/200，正文 17/20
23:02:58 启动失败：127.0.0.1:8791 已经有另一个筛选台在跑（端口锁没拿到）
```

为什么要有这一份：`serve` 那四行启动横幅走 stdout，而 stdout 一旦重定向进文件就变成**块缓冲**，
进程被 `taskkill` 掉时那几行永远写不出来（`data\logs\serve-8765.log` 这种重定向文件常年 0 字节就是这个原因），
访问日志又是刻意静默的——于是"8765 上跑着哪一个实例、什么时候起的"根本没地方查。
`停止：…` 只有 Ctrl+C 正常收尾才写，`taskkill` 掉的那次没有。

顺带修掉一件事：**Windows 上第二次 bind 同一个端口不报错**（`HTTPServer` 带着 `SO_REUSEADDR`），
所以双击两次 `start.bat` 会同时起来两个筛选台，请求落到哪一个全凭运气——上面第二行就是这一条拦下来的：
`data\.serve-<端口>.lock` 是端口锁（空文件，别手动删，进程退了系统自动放）。真要在旁边并排跑一个测试实例，
就 `python cli.py serve --port 8766`。**注意**：锁只认同样带这段代码的实例——服务还没重启过一次的话，
旧实例不持锁，照样可能两个一起听；重启一次才算彻底不会再撞。

命令行方式（不需要界面时用）：

```bash
# 1. 采集（job51 / zhitong 无需登录，开箱可用）
python cli.py collect --platform job51 --query "python" --city 全国 --pages 3
python cli.py collect --platform zhitong --query "python" --city 东莞 --pages 2

# 2. 只有 Boss直聘 要先登录一次（用本机真实 Edge，扫码后回终端按回车验证；懒得记命令就双击 login-boss.bat）
python cli.py login boss --edge
python cli.py collect --platform boss  --query "python" --city 深圳 --pages 5   # 采集时保持 Edge 窗口开着

# 3. 看报告（浏览器打开生成的 HTML）
python cli.py report                     # → reports/report.html
#   注意：这一页的八张图是从 cdn.jsdelivr.net 加载 ECharts 画的，没网（或被人拦了）
#   图就不画，页面上会留一句"图没画出来：…联网后刷新这一页就有图了"，
#   上面的总数/中位数和下面的职位表格都是本地算的，不受影响。
#   筛选台（下一条和 serve）不依赖任何外部资源，断网也全好。

# 4. 静态筛选台：不依赖本地服务，双击 HTML 即可筛选（但不能在页面里采集）
python cli.py browse                     # → reports/jobs-browser.html

# 附：用演示数据预览样式
python cli.py report --demo
python cli.py browse --demo

# 附：导出 CSV（Excel 可直接打开）
python cli.py export
python cli.py export --out 我的投递清单.csv

# 附：给要投的那几条抓职位正文（JD），逐条打开详情页
python cli.py detail --ids 562,560              # 行号是本机库里的 id，不在 CSV 里：鼠标停在筛选台的职位名上就看得见
python cli.py detail --platform zhitong --limit 5   # 自动挑还没正文的职位补抓
# `--ids` 只认行号：给了空值或乱码会一句报错停下，不会当成"没给参数"去自动补抓（那会把一天 20 条额度花光）

# 附：本机大模型打匹配度（只连 LM Studio，不访问招聘平台；先写 data/profile.txt）
python cli.py analyze --limit 5
python cli.py analyze --dry-run               # 只看实际送出去的提示词，不调模型也不写库

# 附：体检（不联网、不开浏览器，也不会打印任何 cookie 的值）
python cli.py status                          # 各平台登录态还剩几天 + 今日额度用了多少
python cli.py status boss                     # 只看某一个平台
                                              # 还会报匹配度那条链的两个前置：data/profile.txt
                                              # 写了没、LM Studio 端口有没有人听，外加待补正文多少条

# 附：纯文本摘要，给邮件/影刀/n8n 当正文用（一行一件事，不联网不开浏览器）
python cli.py digest
python cli.py digest --days 14

# 附：采集留痕——每次采集用的关键词/城市/页数、各类条数，都记在 collect_runs 表里
python cli.py runs                            # 最近 20 次采集（新的在前，含剔掉的原因和被拦的标题）
python cli.py runs --limit 50                 # 看更多

# 附：屏蔽名单与屏蔽规则
# 名单是"单条职位"（你在页面上删过的），规则是"一整类"（按公司或标题关键词）
python cli.py blocked                         # 看名单 + 规则
python cli.py blocked --clear zhitong:10025812   # 放掉某一条（想重看它）
python cli.py blocked --clear boss:*             # 放掉某个平台的全部
python cli.py blocked --keyword 仓库 普工         # 加规则：标题含这些词的一律不进库
python cli.py blocked --company 某某公司          # 加规则：这家公司的一律不进库（整串相等）
python cli.py blocked --drop 关键词:仓库          # 放掉一条规则
```

`digest` 是专门给**外部程序**用的那一个：影刀/n8n 拼邮件正文时直接拿它的输出，不用 parse
`status` 那些给人看的中文长句，也不用去开 SQLite 文件（那个文件是它的，采集/删除/标注都在往里写，
外面多开一个读连接就多一个把写者堵住的来源）。它读的是页面同一份 `fetch_all()`，所以摘要里的数
和你屏幕上看到的必然一致。2026-10-24 在真实库上的输出（`--days` 默认 7，最多 30）：

```
职位摘要 2026-10-24 22:28
库里共 441 条：智通直聘 241 / 前程无忧 112 / Boss直聘 88
今日新增 30 条（额度 30/200）
近 7 天新增：10-18 1 / 10-19 0 / 10-20 0 / 10-21 0 / 10-22 0 / 10-23 2 / 10-24 30
今日分平台：Boss直聘 30
待补正文 261 条（每天 20 条额度），约 14 天补完，待分析 68 条。
匹配度：还没跑过分析——把 data/profile.txt 里的【】填完、把 LM Studio 的端口起起来，再跑 python cli.py analyze
```

三句实话：`今日新增` 按 `fetched_at` 算，重采刷新不重复计数；今天没新增时**不会**硬凑一行
"今日分平台"；匹配度那行在有分数之前只会说"还没跑过"，不会凭空列职位——跑过之后变成
`已分析 N 条，最高 3 条：` 加三行 `88分 职位名 · 公司名（平台）`。
待补正文那行在有平台**现在补不了**时会把天数只按能补的那部分算，并点名是哪家卡在什么上
（写成 `……，Boss直聘 51 条卡在登录凭证已过期 20.8 天，能补的 181 条约 10 天，……`）——
那种时候拿总数除以 20 得到的天数是句假话。
它不发任何平台请求，也不弹窗口；但如果那个 Edge 通道已经开着，它会**接上去读一次
cookie 的名字和有效期**（值不落地，见下节『登录态到底判的是哪一份』），顺手把本地快照刷新成
这一份。没开就跳过这一步，不拦任何东西。

一次采集建议一天跑 1~2 个关键词即可，多跑几天数据自然积累。
看腻了的、明显不投的，直接在筛选台上删掉（见「删掉没用的职位」一节），不用碰数据库文件。

导出的 22 列里，除了平台原文的 `salary_raw`，还给了 `salary_min / salary_max /
salary_months / salary_annual_wan`（年薪估算，万元/年：月薪中位数 × 发薪月数，
平台没写月数按 12 薪算），以及 `skills / welfare`（已按下节统一口径，` / ` 分隔），
在 Excel 里可以直接按年薪或技能排序筛选。`description` 是职位正文，只有抓过的
那条才有值（见下节）；`status / note` 是你自己标的投递进度（见「投递状态」一节）。

薪资那一列的口径（`db.py` 的 `parse_salary`，单位统一成 **K/千**）：

- `15-25K`、`8千-1.2万`、`1.2万以上` 这些区间/单值都认；`万` 按 10K 折算。
- **只写一个数**（`15K`、`15K以上`、`2万`）时上下限都记成这个数——按下限口径留着，
  不去猜平台没给的上限。
- **没有单位的裸数字**按量级判：`>=500` 当"元"（`3000-5000` 是 3~5K，不是 3000K），
  `<500` 当"K"（`8-12` 是 8~12K）。不判的话筛选台薪资轴会被 3000K 撑爆。
- `面议`、`200元/天`、按小时/按年计的这些解析不出月薪区间（`salary_min/max` 留空，
  `salary_raw` 保留原文），不进直方图、不算中位数。
- `·14薪` 只用来推年薪，不改月薪区间。
- **读的时候还会按原文兜一次**（`db.fetch_all`）：数值列是入库那一刻算的，口径升级之前入库、
  又没再采第二遍的老行就一直是空（2026-10-22 真库实测 2 条：`7千-1.3万`、`8千-1.2万`）；
  Boss 通道另有自己一套只认 `N-MK` 的写法，`x千-y万` 那种它算不出来。兜底只在读取侧，
  库里那几列不动，页面/报告/CSV/digest 一起好；真解析不出的（`面议`、`8-16万/年`）照旧留空。
  补完之前是 394 条有区间，之后 396 条。

## 抓取条件与相关性闸门

搜 "IT" 却抓回焊工、叉车司机、洗水杂工，不是解析写错了，是平台就这么给的。
2026-10-12 拿 `job5156` 的 "IT @ 东莞" 结果页逐条对过，不相干的岗位有三个来源：

1. **置顶推广位**：智通把付费置顶的岗位塞在同一个列表 `<ul>` 里，那一页最前面 5 条
   （焊工 / CNC编程 / 总经理助理）跟关键词毫无关系，判据是条目上的 `data-top="true"`，
   解析器直接跳过它们。
2. **城市参数被忽略**：传了 `city=东莞`，同一页照样返回惠州，甚至广西贺州。命令里写了
   城市就以命令为准，`jobstats/relevance.py` 按城市名比对（`东莞市` 认作 `东莞`）拦下。
3. **短关键词按子串命中**：搜 `IT` 会带出 `TITOK运营`、`FIT模师傅`。所以只给 **≤3 个字母
   的纯英文短词**加词边界判断：标题里 `IT` 得独立成词（`IT工程师`、`硬件IT储干` 都算），
   被埋在一个更长的英文单词里就不算。技能标签放宽成子串匹配，`ITIL` 这类真相关的缩写
   不误杀。长词（`python`、`软件开发`）**不拿字面判断当剔除理由**——实测那种搜索返回的
   都是对口岗位，加规则反而会把"后端开发工程师"这种标题里不写语言的岗位挡掉。
4. **中英混写的关键词（`IT运维`）以前等于没判**：上面第 3 条只管纯字母短词，`IT运维`
   进不去，于是 2026-10-17 那趟 41 条智通入库里有 11 条跨行的（锅炉操作工、污水处理
   操作员、物业项目负责人、体系工程师、技术员助理、业务员、储备干部、光伏运维1……）。
   现在判两件事：
   - **关键词命中放宽到中文**：英文部分按词边界，中文部分切**二字组**（`软件开发` →
     软件/件开/开发），所以"后端开发工程师"照样算命中 `软件开发`。命中只当放行，不当剔除。
   - **平台自己标的职类当方向**：智通每条岗位带 `data-first`/`data-second`，是
     「公司行业-职类」，第二段是**职能**（锅炉操作工标的是 `生产制造-技工`，`程序员`
     标的是 `AI/互联网-运维/技术支持`）。标题没命中关键词、职类又不是技术方向，就拦。
     只有智通开这个判据（通道上的 `FAMILY_GATE`）：Boss 的 `industry` 装的是**公司行业**，
     拿它判方向会误杀"园区弱电IT运维工程师"（那家标的是环保），前程无忧列表压根不给。
5. **标题本身就是一线操作岗/跨行业运维的说法**：普工、模师傅、装卸搬运工、叉车司机、
   煮饭阿姨、丝印/移印技工，以及"是运维但不是 IT"的光伏运维、污水运维、空调维修工。
   这跟关键词无关，判的是"这条不是办公室技术岗"，所以关键词命中了也拦（`光伏运维1`
   就是命中 `运维` 混进来的）。福利/兼岗说法（包吃住、长白班、两班倒、司机、跟单）
   **单个不算证据**：库里实测有 `IT工程师（包吃住）`、`IT技术支持兼行政司机`、
   `IT专员/IT主管（包吃住+双休+五险一金）`，那都是真 IT 岗；两个一起出现才拦，
   `7000-9000技术员包吃住 五险一金长白班运维` 就是这么被剔掉的。

跑完一趟会告警剔了多少、为什么剔、剔掉的**具体是哪些标题**（复跑今天的真实 47 条实测）：

```
  跳过平台置顶推广位 5 条
[zhitong] 本次去重后采集 30 条
  相关性闸门另剔掉 11 条：标题像一线操作岗 6 条、平台职类不是这个方向 5 条（想放宽就别传具体城市，或用更长的关键词）
  剔掉的：技术员助理（平台职类不是这个方向）、体系工程师（平台职类不是这个方向）、安全工程师 （安服方向)（平台职类不是这个方向）、污水处理操作员（标题像一线操作岗）…共 11 条
```

要知道这几件事：

- **闸门在入库之前**，所以被拦下的条目不占每日 200 条额度；但整页都被拦下**不算翻到头**，
  还会继续翻页（下一页可能全是相关的）。停止翻页只看"这页有没有**没见过的** id"，而这个
  "见过"是按**整页**的职位编号算的（被闸门拦下的也算见过）——早先这里只跟"闸门放行后"的
  集合比，于是关键词每页被拦光时它判定"还是新页"，会一路翻到页数上限——`--pages` 给多少就
  白翻多少页（智通那种同一页反复出现的口径尤其明显）。
- 惠州、深圳这些邻近城市现在会被拦。想看就**别传 `--city`**（或传 `全国`），或者按城市
  各跑一趟——后者更好，因为城市是他自己选的口径。
- **Boss直聘 那条通道现在也过闸门了**，接在公共落库口 `collectors/__init__.py` 而不是采集器
  里：那条通道没声明 `SELF_GATES`，所以整轮记录在写库前统一判一遍，前程无忧和智通自己已经
  判过的不会被二次判断（否则同一批记录被两套口径过滤，页面上的剔掉条数会跟采集器打印的
  对不上）。10-12 那次说"boss 的 37 条没噪声"所以留着不接，2026-10-13 的 18 条推翻了它——
  里面混着 仓库管理员 / 新仓急招小班长 / 打印机维修 这类 5 条，拿现成闸门复跑正好剔掉这 5 条。
  **Boss 采集器本体（`boss.py`）一行没动。**
- 闸门看的是标题、技能标签，加上智通给的那一段职类。所以它仍然拦不住"标题里写了 IT
  但其实是修打印机"的那种；那类用**屏蔽规则**按关键词或公司批量拦
  （`python cli.py blocked --keyword 维修`），见「删掉没用的职位」一节。
- **误杀只能从留痕里复核**：闸门拦下的行不入库，库里查不到。每趟采集把「原因 → 被拦标题」
  存进 `collect_runs.drop_titles`，`python cli.py runs` 会连明细一起打出来。自己过闸门的通道
  （前程无忧、智通）不经过公共落库口，靠采集器每页交一次 `on_drop` 才留得下这份明细。
  这次复跑今天 41 条智通，已知误杀一条：`安全工程师 （安服方向)`（安服是 IT 安全服务，
  可平台把职类标成了 `能源/环保/农业-环保`）。看到不想要的拦截，就用更长的关键词
  （长词不做字面剔除）或别传 `--city`；词表本身在 `jobstats/relevance.py` 顶部，改一行就能放宽。

## 采到 0 条时先分清四种原因

"没采到"至少有四种完全不同的含义，处理方式也相反（该重跑的你停了，该改代码的你去扫码）。
所以采集器在停手前会把判据打在终端上，**看最后一条提示**而不是看条数：

| 终端上说的话 | 真实原因 | 该怎么办 |
|---|---|---|
| `本页没有职位条目（无结果或已翻到头）` | 这个"城市 × 关键词"口径里平台就没货 | 换关键词或换城市，代码没问题（实测东莞 `python爬虫` 就是这个） |
| `本页 N 条全是平台置顶推广位，没有关键词命中的结果` | 同上，只是付费位占满了首屏 | 同上 |
| `本页看到 N 个职位条目却一条都没解析出来：…结构变了…要改的是 zhitong.py 的选择器，不是你的账号` | 平台改了类名 / `data-*` 埋点字段 | **改采集器**，扫码、换关键词都没用。前程无忧那条对应的是 `N 张卡片都取不到职位编号…要改的是 job51.py 的 _parse_sensors` |
| Boss 的 `code=37 您的环境存在异常` | 翻太快，或登录态过期 | `python cli.py status` 一测就知道是哪种 |

`python cli.py status` 是专门用来做最后那一格的：它只读项目外的登录态文件，
打印文件路径、存了多少个 cookie、这份是什么时候存的，然后逐个看 `bst` / `zp_at`
的有效期——`还剩 X.X 天` / `已过期 X.X 天` / `有，但是会话 cookie（关掉浏览器就失效）` /
`没有（登录判据缺失）`，最后一行给结论（都在且没过期时它会说"采集还是 0 条的话，
看平台返回的 code 再判"）。全程不联网、不开浏览器，**一个 cookie 的值都不会打出来**——
那两个值等同于你的账号凭证。

2026-10-13 的真实输出（用的就是那份 09-26 的登录态）：

```
[boss]
  文件：C:\Users\<你的用户名>\AppData\Local\job-stats\auth\boss_storage.json
  共 26 个 cookie，这份存于 2026-09-26 17:33
    bst: 已过期 9.8 天
    zp_at: 已过期 9.8 天
  结论：bst、zp_at 已经过期。再敲采集命令也没用，重新扫一次码才是正解（这也是 code=37 最常见的那个来源）。
[job51]
  该平台不需要登录，没有登录态要管。
[zhitong]
  该平台不需要登录，没有登录态要管。
额度：今日已入库 18/200 条，正文 0/20 条。
```

顺带一条容易搞反的：**0 条入库不占每日额度**（额度按实际写进库的条数算），
所以换关键词重试不会把今天的额度吃光。但反过来，**删掉今天已入库的行会把额度还回来**，
别把删除当成重置额度的办法——那是每天 200 条上限的意义所在。

## 影刀 RPA：每天早上的登录巡检

`cli.py status` 不联网、不开浏览器，这种命令用 Windows 计划任务就能跑，本来轮不到 RPA。
它真正顶用的地方是**发现登录态死了之后那一下**：把消息推到你手机上、把 Edge 扫码窗口顶到面前，
让重扫发生在当天早上八点，而不是你哪天想起来采 Boss 的时候。
（采集那一层别交给影刀：`jobstats` 自己带 Playwright、去重和 200/20 两条额度上限，
再开一个爬虫抢同一份额度只会互相踩。）

### 流程只读一个口子

`login-check.bat`（项目根，双击也能自己试）跑 `cli.py status boss`，把输出定成 UTF-8 写到
`data\logs\login-check.txt`。为什么要绕一道文件、而不是让影刀直接捕 stdout：命令重定向出去时
Python 按本机代码页写字节——2026-10-21 实测，不设 `PYTHONIOENCODING` 那份落的是 GBK，
按 UTF-8 读连一个汉字都解不动，判据自然一个也匹配不上。
2026-10-22 起 `cli.py` 自己在 `main()` 里把 stdout/stderr 定成 UTF-8 了（`_force_utf8_output`，
实测 `cli.py digest > 文件` 不设环境变量落的就是 UTF-8），bat 里那句 `PYTHONIOENCODING`
仍然留着：它管的是**还没进到 cli.py 里来**的那部分——比如 `.venv` 没了时的
`ModuleNotFoundError` 堆栈，那是 Python 自己打的，我们没机会改。读的一方手动选 UTF-8 就不靠运气。
2026-10-24 21:26 实测那一份的内容：

```
[boss]
  文件：C:\Users\11\AppData\Local\job-stats\auth\boss_storage.json
  共 17 个 cookie，这份存于 2026-10-24 22:30
    bst: 还剩 7.2 天
    zp_at: 还剩 7.2 天
  结论：登录凭证都在且没过期。采集还是 0 条的话，看平台返回的 code 再判。
额度：今日已入库 30/200 条，正文 16/20 条。
分析前置：本机自述文件 还有 8 处【】没填（如 【补：几年 / 是否工作用过】）——填掉这些才能算匹配度，analyze 会拒绝带着占位跑。
          LM Studio 端口 127.0.0.1:1234 没人听：模型没起来，analyze 会直接失败。

  正文是分析的瓶颈：按每天 20 条算，补完这 261 条要 14 天。别等全补完，用 `detail --ids 行号` 先给要投的那几条补。
```

（2026-10-24 由 `login-check.bat` 真跑出来的一遍，不是手写的示例。自述文件从没写、
写到一半、填完了三种情况，`分析前置` 那行都会照实说。）
上面这份是**重新扫过码之后**的样子。之前那份报的是"已过期 20.8 天"，而当时 Edge 里
其实还留着 7 天多的有效凭证——差别在于快照文件不会自己更新，见下一节
『登录态到底判的是哪一份』。`结论` 那行读的是文件里的日期，所以它跟着快照走；
快照由 `status` 在通道开着的时候刷新（只写名字和有效期都在的那一份）。
"其中 Boss直聘 N 条现在补不了"那行只在实时通道确实拿去判、判出来不能用时才出现，
天数也只按能补的那部分算——那种情况下拿总数除以 20 得到的天数是句假话。
**这几行只是说明，不是巡检判据**，影刀那边别去匹配它们。

判据就是这几个词，**它们是接口，不是文案**——`tests/test_core.py::TestLoginStateReport`
里 `test_healthy_state_matches_no_rpa_phrase` / `test_every_broken_state_matches_an_rpa_phrase`
两个用例钉着：改说法会红，别顺手润色。

| 匹配文本 | 意思 |
|---|---|
| `已过期` | 登录态死了，采了也是 0 条 / code=37 |
| `还没保存过登录态` | 从没扫过码（auth 目录里没有那份文件） |
| `判据缺失` | 文件在，但里面只有匿名 cookie，那次是匿名访问 |
| `看不出有效期` | 会话 cookie，判不出来，只有真采一次才知道 |
| `还剩 ` + 数字 | 还活着；数字用正则 `还剩 ([0-9.]+) 天` 抓 |

### 影刀里的步骤

1. **定时**：每天 08:00。勾上"错过后尽快补跑"（各版本叫法不一样，不勾的话周末开机就不巡检了）。
   前提是影刀客户端开机自启且登着——它跑在桌面上，机器睡眠就什么都不会跑，这条和 n8n 在 Docker 里
   跑是两回事。
2. **执行命令行**：`cmd /c "D:\code\2026-09-16-22-13-38\job-stats\login-check.bat"`
   别看它的返回值——那个 bat 永远 0，判据全在下一步那份文件里。它跑不成也会留下一个
   没有 `结论` 的文件，那正是分支表第 1 行管的情况。
3. **读取文本文件**：`D:\code\2026-09-16-22-13-38\job-stats\data\logs\login-check.txt`，
   编码手动选 **UTF-8**，存进变量 `TXT`。
4. **分支**，从上往下命中即停：

   | 顺序 | 条件 | 动作 |
   |---|---|---|
   | 1 | `TXT` 里没有 `[boss]`，或没有 `结论` | **巡检自己没跑成** → 发"巡检没跑成"消息（模板在下面第 5 步），判定记 `broken` |
   | 2 | 含 `已过期` | 发"扫码"消息，天数用 `已过期 ([0-9.]+) 天` 抓出来带上 |
   | 3 | 含 `还没保存过登录态` 或 `判据缺失` | 发"扫码"消息（这俩都是"根本没有登录态"，别报成"过期"） |
   | 4 | 含 `看不出有效期` | 发"判不准"消息：措辞就是"只能采一次才知道"，**不要**顺手加一次自动采集——那一页下去就占掉当天 200 条额度里的一截 |
   | 5 | 正则抓到 `还剩 ([0-9.]+) 天` 且 < 2 | 发"快到期"预警（今天还能用，明天就死） |
   | 6 | 以上都不命中 | 健康：不发东西，只往 `data\logs\login-check.log` 追加一行 |

   第 1 条放最前面是故意的：判据匹配不上时宁可吵一句，也不要装成"健康"——
   一声不响的巡检比误报的巡检难发现。
5. **消息**（第 2/3 步这种要动手的，把路径写进正文，手机上就能照着做）：

   ```
   [招聘采集] Boss 登录态已过期 17.7 天（10-21 08:00 巡检）
   今天想采 Boss 先扫一次码：双击 D:\code\2026-09-16-22-13-38\job-stats\login-boss.bat
   Edge 会弹出登录页，扫完回到黑窗口按一次回车才算存好。
   ```

   分支表第 1 行另写一条，别和上面混用——那种情况要修的是环境，不是账号。
   2026-10-21 实测过这条路径：把 `.venv` 临时改名再跑 bat，它退回系统 python，而那上面没装
   playwright，落下来的就是一串 `ModuleNotFoundError: No module named 'playwright'`，
   `结论` 那一行根本不存在（bat 自己照样回 0——所以别看返回值）。

   ```
   [招聘采集] 登录巡检自己没跑成（10-21 08:00）
   login-check.txt 里没有"结论"那一行。多半是 .venv 被删了或挪了位置，
   双击 install.bat 重装一遍，再双击 login-check.bat 看文件里有没有"结论"。
   ```

   推送到手机这一格我没法替你验——那是你影刀客户端里的组件（企业微信/钉钉/影刀 App 推送/邮件，
   看哪个已经配好了），流程里就它可变。要是都不想配，退一步用影刀计划任务自带的运行结果通知，
   代价是"需要扫码"得做成失败退出才能触发。
6. **想让它顺手把窗口顶到面前**（可选，只在人已经坐在桌前时开）：
   第 2/3 步的分支里加一条「运行程序、**不等待结束**」执行
   `cmd /c "D:\code\2026-09-16-22-13-38\job-stats\login-boss.bat"`。
   别用"等待结束"：那个 bat 结尾有 `pause`，会把流程一直挂住到有人按回车。
7. **追加一行日志**，健康与否都记，这样提醒被你划掉了也留痕：

   ```
   2026-10-21 08:00 | expired | -17.7 | 已发消息
   ```

   字段是 时间 | 判定(healthy/expired/missing/session/soon/broken) | 剩余天数 | 有没有发。
   这个文件是影刀写的，跟第 3 步那份（每次覆盖）不是同一个，别读错。

### 顺手把每天的统计也发一份（同一套积木）

**抓取别让影刀点网页**，到点叫它跑命令行就行，和第 2 步一个模式：

```
cmd.exe /c "cd /d D:\code\2026-09-16-22-13-38\job-stats & .venv\Scripts\python.exe cli.py collect --platform zhitong --query IT运维 --city 东莞 --pages 3"
```

画布里点网页的那套没有去重、没有 200/20 两条额度、没有 3~8 秒限速、没有每页落库，
同一条职位会天天重复入库，Boss 那个 `code=37` 也是这么来的；而且 Boss 用的是你真实 Edge 的
登录态（CDP 接管那个窗口），影刀再去操作同一个浏览器就是两个程序抢一个窗口。

**统计走 `cli.py digest`**（见「使用」一节，一行一件事的纯文本），别去 parse `status` 的中文长句，
更别让影刀直连 `data\jobs.db`：那要装数据库驱动、写 SQL，而且库只有一个写者，多一个读连接
就多一个 `database is locked` 的来源。

**邮件这一半我建议留给 n8n**：影刀要发信得填 SMTP 授权码，那个码会存在影刀的流程里，
跟着应用导出/团队共享一起走——和"登录态放项目外"是同一件事。影刀真正顶用的还是桌面那一下
（弹窗、把扫码窗口顶到面前）。

## 职位正文（JD）

统计口径只能告诉你"市场给多少钱"，投递时要看具体那条 JD 写了什么要求。所以正文
单独一张表 `job_details`，**默认不去抓**——逐条打开详情页比翻列表页容易触发风控得多。

- **每日额度单独算**：`DETAIL_DAILY_CAP = 20` 条/天，抓满就熔断，和列表额度互不影响。
  每抓一条照样随机等 3~8 秒。
- **怎么看**：筛选台每行末尾的『抓正文 / 看正文』按钮，点开在这行下方展开；
  或 `python cli.py detail --ids …`；或导出 CSV 看 `description` 列。
- **拿不到正文的平台说实话**：前程无忧那批行的按钮写成『不抓正文』，点开只在这行下面说明
  原因，不发请求、不占额度；`cli.py detail --platform job51` 开头回的就是同一句话。
  能力表是 `details.NO_DETAIL`，接口和页面都引用它——以前它报"职位可能已下架"，
  可职位明明还在平台上，那是把能力限制说成了职位状态。`status` 里的**待补正文**
  也已经把这类平台排除掉（旧口径 325 条里有 93 条是前程无忧的，永远补不上）。
  要这一条的 JD 只有绕路：能和智通/Boss 的行对上就在筛选台点『另见』借对面那条的正文
  （见下一节『跨平台对照』），对不上就自己打开详情页复制——程序不去碰那个滑块。
- **登录态到底判的是哪一份**：真身在 Edge 配置目录（`%LOCALAPPDATA%\job-stats\edge-profile`）里，
  `auth\boss_storage.json` 只是份**快照**，而且平时没有任何命令会刷新它。所以"扫过码了但页面还说
  已过期 20.8 天"不是幻觉：2026-10-24 实测，通道里 bst/zp_at 还剩 7.2 天，那份快照还停在 9-26。
  闸门（`browser.login_block_reason`）因此**只认实时通道**——那个 Edge 窗口开着就接上去读一次
  cookie 的名字和有效期（值一律不碰），凭证是好的就顺手把快照刷成这一份；通道没开时它不拦，
  因为 `boss.ensure_window()` 会把窗口弹回来，`collect_details` 在弹窗之后再问一次，
  那时候才有证据。拦下来时 `detail`/`status`/`digest` 和筛选台的『抓正文』说的是同一句话
  （哪个平台、什么原因、多少条这次不抓，"双击 login-boss.bat 重新扫码之后再点"），
  不是"职位可能已下架"；只跳过那一家，其余照常补。
  这条链改之前有两处坑：拿着过期 20 天的凭证弹 Edge 窗口、真的朝 Boss 发请求（风控记在账号上），
  以及一批混合职位里只要有一条 Boss 就把整批中断——都修了，但**别把"文件里的日期"当账号死活**，
  这一条就是那个教训。`status`/`digest` 的**待补天数**只按能补的条数算，卡住的部分单独点名。
- **哪些平台抓得到**（2026-09-27 实测）：
  | 平台 | 正文 | 说明 |
  |---|---|---|
  | 智通直聘 | ✅ 纯 HTTP | 正文在 `<pre class="pos-desc">` 里原样带换行，连浏览器都不用开 |
  | Boss直聘 | ✅ 走 Edge 通道 | 正文在 `<div class="job-sec-text">`，用登录上下文直接 GET 详情页即可，不开标签页 |
  | 前程无忧 | ❌ 不抓 | 详情页 `jobs.51job.com/...` 直接弹滑块验证，按红线立刻停手，代码里一个请求都不发 |
- **只存公开内容**：正文和详情页关键词（`keyword_tags`）进白名单
  `ALLOWED_DETAIL_FIELDS`，HR 姓名/头像/联系方式那一段压根不解析。
- 同一职位重复抓会**覆盖**旧正文（招聘方会改 JD）；页面按钮只在没有正文时才发请求，
  想重抓用 `python cli.py detail --ids … --force`。
- 详情页关键词（`keyword_tags`）比列表页更全，只存在 `job_details` 里，但**读取时会兜底**：
  这一行 `jobs.skills` 清洗后为空、而它抓过正文，就用正文那行的关键词顶上技能列，界面上标一个
  黄色『来自详情页』标签。库里 `jobs.skills` 仍是平台原文——口径见下面『技能列的两个来源』。

## 跨平台对照（同一家公司在别处也发了）

同一个职位在三个平台各发一遍很常见，两家写的薪资还可能不一样——只看一家会误判行情。
`jobstats/crossref.py` 在**读取侧**按"归一后的公司名 + 归一后的职位名"分组，只有同一组里
真的出现 ≥2 个平台才标注，界面上标题下方多一个紫色小标签『另见 智通直聘』，点开在这行下方
展开对照面板：对面那条的平台、薪资、城市、最近见到日期，和正文按钮。**不新增列**（表头仍是
14 列，面板 `colSpan=14`），也不写库，改归一规则不用重采。

归一化的两处判据：

- **公司名**：去空格，然后一层层剥掉结尾的法律形式和"科技/技术"后缀
  （`股份有限公司`/`有限责任公司`/`有限公司`/`分公司`/`集团`/`科技`/`技术`），剥到剥不动为止。
  要循环剥是因为一家可能连着两个后缀。`东莞市微科光电科技有限公司` → `东莞市微科光电`。
- **职位名**：去掉括号里的内容（`IT运维工程师（网络方向）`）、标点空格，再转小写。

**措辞只说"另见"，不说"重复"**，因为这一判据只会漏报不会认错：漏报来自代招换了主体名、
标题写法不同、或者两家根本没采同一个关键词；面板的提示语把这句写在了脸上。

密度实测（2026-10-18，库里 409 条：前程无忧 112 / 智通 239 / Boss 58）：**只有 2 组**对得上，
三平台都有的 0 组。

| 归一后的键 | 两边写的薪资 |
|---|---|
| `东莞市微科光电` + `it运维工程师` | 前程无忧 7-9千 ／ 智通 7.5-8.5K |
| `东莞市稳畅电子制品` + `it运维工程师` | 前程无忧 6.5-7.5千 ／ 智通 6.5-7K |

之所以这么稀，不是"平台之间不重叠"，而是**三个平台各自用的搜索关键词不同**——同一批关键词
在两家都采一遍，命中率立刻上去。想要这个功能更实用，就用相同关键词多平台各采一轮。

顺带一条实际用处：前程无忧自己抓不到正文（见上一节），但它的行只要能跟智通/Boss 的行对上，
点开对照面板就能**借到对面那条的正文**——这是程序自动拿到这一条 JD 的唯一合规路径
（另一条只能你自己打开详情页复制，程序不去碰那个滑块）。已实测：借到的第一次点
真的去智通抓回 378 字正文（占掉今日 20 条额度里的 1 条），之后再点服务端直接回 `job_details`
里的缓存——页面对本地接口照发一次请求，但不碰平台、也不再多占额度（库里的 `job_details`
仍是 28 行、今日仍只 1 行）。

## 投递状态（本地标注）

采回来 180 条之后，真正的问题变成"我投了哪几条、哪条约了面"。所以 `jobs` 表另有两列
`status`（想投 / 已投 / HR已读 / 约面 / 已面 / offer / 不合适）和 `note`（备注，200 字以内）。

- **怎么用**：筛选台每行的『状态』下拉选一下，旁边备注框写一句（**失焦或回车才存**，
  框子绿一下边框就是存好了）。筛选条上的『状态』下拉里选**未标注**，就是"还有哪些没处理"，
  用它挑下一批要投的。
- **它不访问任何平台**：这两列记录的是你自己做过的动作。刻意**不**去做"从 Boss 同步
  HR 是否已读"那种功能——那要用你的登录会话去读私域沟通数据，超出采集红线，也不稳定。
- **采集器写不进这两列**：`status/note` 不在 `ALLOWED_FIELDS` 白名单里，唯一的写入口是
  `db.set_status()`。同一个关键词反复重采也不会把你标过的状态冲掉（入库走的是
  `INSERT OR IGNORE`，已存在的行整行跳过）。
- **老库自动补列**：`init_db()` 会先查 `PRAGMA table_info(jobs)` 再 `ALTER TABLE` 补这两列，
  已有的职位一条不动，老行的状态读出来是空字符串。
- 导出 CSV（`python cli.py export`，22 列）和页面上的『导出当前结果 CSV』都带上这两列，
  在 Excel 里按 `status` 一排序就是一份投递台账。


## 匹配度分析（本机大模型 + n8n）

采回来一堆职位之后，下一个问题是"哪几条值得投"。让本机跑的模型读 JD 给个 0~100 的匹配度，
存在 `job_analysis` 表里，筛选台每行多一列『匹配度』，悬停显示理由和技能缺口，
排序下拉里选**匹配度从高到低**就能从上往下挑。

```bat
.venv\Scripts\python.exe cli.py analyze --limit 5
.venv\Scripts\python.exe cli.py analyze --dry-run       :: 只看实际送出去的提示词，不调模型
.venv\Scripts\python.exe cli.py analyze --redo          :: 改完提示词把算过的重算一遍
```

- **先写自述**：`data/profile.txt`（纯文本，一行一条：会什么、几年、学历、期望城市、
  月薪下限、不想干的方向）。匹配度得有参照，没这个文件命令会直接告诉你该写什么。
  它不进数据库、不进 CSV、只发给本机 127.0.0.1 上的模型。
- **模板里的【】必须填掉**：`analyze` 看见还有 `【…】` 就一句报错停下，不会开算——
  尺子上还写着"【几年】"，算出来的分既不该存库、更不该拿去排序。`status` 那行也从
  "已就绪"改成"还有 8 处【】没填（如 …）"。想先看送出去的内容用 `--dry-run`，
  预览不发消息也不写库，占位没填照样能看。
- **只算「已有正文」的职位**：`cli.py analyze` 挑的是 `db.pending_analysis()`——正文已经在
  `job_details` 里、且还没算过分数的。所以这一步**不会访问任何招聘平台**，也不会吃掉
  每日 20 条的正文额度。想先给某几条抓正文，用 `cli.py detail --ids`。
- **调模型的是本项目**：`jobstats/analyze.py` 用标准库 `urllib` 打 LM Studio 的
  OpenAI 兼容接口（默认 `http://127.0.0.1:1234/v1`，`--url` 可换 Ollama 之类）。
  提示词和分档细则集中在那一个文件里，`--dry-run` 能原样看到送出去的内容，比在画布上
  拼节点好版本管理；`temperature` 钉死 0，同一次运行里同一条职位重复算是同一个分。
  `--model` 不给就自动问 `/v1/models` 要 LM Studio 当前加载的那个，省得抄模型 id。
  依赖仍然只有 playwright 一个，没为模型加任何包。
- **一次要跑多久（2026-10-12 实测，别按别人的机器估）**：`qwen3.5-9b` 是思考型模型，
  LM Studio 把思考链单独放在 `reasoning_content`（8~1.5 万字），我们只要最后那 200 字
  JSON，所以一条平均 **65 秒**（最快 43、最慢 87），默认 20 条一轮约 **20 分钟**。
  接口输出稳定在 ~50 token/秒，走 `127.0.0.1` 还是本机网卡地址都一样。
  试过往提示词里加 `/no_think` 关思考：8 条对照下来只快 1.16 倍（在抖动范围内，8 条里有
  2 条反而更慢），思考链并没有真被关掉，所以没往代码里加。`max_tokens` 千万别设——
  思考会先把额度吃光，正文回来是空的。
- **分数怎么用才不踩坑**：同一条职位换个问法或改一下自述用词，能差 10~20 分，
  35~58 这段本来就在"投不投"的边界上。所以把 `score` 当**排序依据**用（页面按匹配度
  从高到低排，从头往上看），别当 50 分划线过滤器；真要划线就给自己留个上下 10 分的余量。
- **单条失败只跳过这条**，连着 3 条都没跑通就整体停手（多半是服务没开或模型答歪了，
  别让 20 条都耗在同一个坑里），并报出实际收到的内容。
- **老库自动多出一张表**：`init_db()` 里是 `CREATE TABLE IF NOT EXISTS`，不用迁移脚本，
  没分析过的职位那一列显示 `—`。

给 n8n 的口子（都带 `X-Token` 请求头）——现在 n8n 只需要"定时叫它跑 + 把结果攒成摘要发信"：

| 用途 | 接口 |
|---|---|
| 取全部职位（含已算出的 `score/matched/gaps/reasons`） | `GET /api/jobs` |
| 取"有正文、还没分析"的若干条，正文一起给（只读） | `GET /api/pending_analysis?limit=20` |
| 看哪些已经分析过 | `GET /api/analysis` → `{"keys":["boss:1234", ...]}` |
| 回写一条结果（想在 n8n 里自己拼 prompt 就走这个） | `POST /api/analysis` |

摘要那一半也可以完全不在 n8n 里拼：`python cli.py digest` 直接吐纯文本（一行一件事），
n8n 那侧就是"跑命令 → 把 stdout 塞进邮件正文"，不用自己数、也不用读上表那几个接口。

回写的请求体（`score` 可省略，表示模型没给出分数，仍会落一行，免得外部反复重跑同一条）：

```json
{"platform":"boss","platform_job_id":"1234","score":88,
 "matched":["Python","Django"],"gaps":["K8s"],
 "reasons":"技术栈吻合","model":"qwen3.5-9b"}
```

字段之外的键会被拒（400），`score` 超出 0~100 也拒，库里不存在的 `platform_job_id` 返回 404
——外部脚本写不进来历不明的行。

服务只在需要让容器里的 n8n 连进来时才改监听：

```bat
set JOBSTATS_TOKEN=换成你自己的长随机串
.venv\Scripts\python.exe cli.py serve --host 0.0.0.0 --no-browser
```

- **为什么要设 `JOBSTATS_TOKEN`**：不设就每次启动随机一个令牌，页面照样能用（令牌随
  HTML 一起发出去），但外部程序重启后就拿不到了。
- **为什么要 `--host 0.0.0.0`**：默认只监听 `127.0.0.1`，容器里的 `host.docker.internal`
  连不进来。但这也意味着同网段别的机器能访问这个服务，所以**必须**配固定令牌，
  并建议用 Windows 防火墙把该端口限给 Docker 的虚拟网卡。
- n8n 侧地址：`http://host.docker.internal:8765`。
- **模型这头不用开局域网**：现在是本机的 Python 直连 `127.0.0.1:1234`，LM Studio 保持
  默认的仅本机监听就行；只有你坚持让容器里的 n8n 直接调模型才需要它监听 `0.0.0.0`。
- **不要让 n8n 直接读 SQLite**：Docker Desktop 的 bind mount 给不了可靠的文件锁，两个进程
  同时写会顶掉数据。库只有本项目的进程在写，外部一律走上面的接口。
- **每轮限量**：一次别超过 20 条（`--limit` 默认就是 20），跑完每条都报了实际用的秒数，
  最后再给一个平均值——按你自己机器上测出来的数排轮次，别照搬别人的估计。
- 正文按 `config.JD_MAX_CHARS`（默认 2000 字）截断后再送，本地模型上下文有限。

合规边界和投递状态那两列一样：`score` 等字段**刻意不并进 `ALLOWED_FIELDS`**，采集器写不到
它们，重新采集也冲不掉已有的分数（入库走 `INSERT OR IGNORE`）。喂给模型的只有公开 JD 和
你自己写的自述，数据不出本机。


## 删掉没用的职位（可撤销）

采多了总会有一堆不想看的：外包、异地、薪资对不上。清掉它们不用碰数据库——
筛选台每行末尾有个『删』，筛选条下面还有一个**删除当前筛选出的 N 条**，
按你正看着的那一批来删，条件只用说一次。

- 确认框里会**列出前 10 条的标题/公司/城市**，批量删最容易出的错是"我以为我筛对了"。
- 删的只有本机 `data/jobs.db` 里的记录：**不会访问任何招聘平台**，也不影响你已经投出去的
  申请。这条职位的正文和匹配度一起清掉。
- 删完页面给一次**撤销**（"撤销这次删除"）。批次是服务端写在 `data/trash/<批次>.json`
  里的，页面重开了也还能撤；撤销只有一次机会，撤完那批就作废。
- 放回时走 `INSERT OR IGNORE`：删掉之后又新采集、新标注的那条不会被旧数据顶掉。
- 撤回来的行按 `last_seen_at`、投递状态、标注逐列原样放回（2026-10-23 在 `data/jobs.db`
  的副本上比过 4 条真数据）。以前 `last_seen_at` 不在放回列里，撤回来的在职职位会退回按
  **第一次采到的日子**判「疑似已下架」——第一次采到在 14 天前、其实天天都在被重采的那种就是这样。
- **只有本机行号会重新排**：撤销是插一条新记录，`id` 换新号（自增号不会回收给别人，所以
  老的行号只是空着，不会被别的职位顶替）。你写在纸上的行号如果正好赶上一次删除又撤销，
  就按鼠标停在职位名上显示的当前号为准。
- 删掉的职位会同时进**屏蔽名单**（`blocked_jobs` 表，只记 `平台:职位编号` + 标题/公司）：
  第二天定时跑同一个关键词时，采集器一看到这些编号就跳过，**不会把你刚清掉的噪音原样采回来**
  ——否则同样的外包/异地岗要每天删一遍。拦掉的条数会在终端和任务日志里报出来
  （`入库新增 7 条、刷新 28 条、屏蔽名单拦掉 3 条`）。名单本身用 `python cli.py blocked` 看，
  `--clear 平台:编号` 放掉单条、`--clear boss:*` 放掉整个平台。
- **撤销那次删除会顺手把这几条从名单里放掉**，所以"删错了又撤回来"的职位下次采集照常入库。
  反过来：撤早了、或者当时只是看腻了想临时藏起来，先记着它现在在名单里。
- 名单只能一条条记（主键是 `平台:职位编号`）。**同一类噪音换家公司就会再来一遍**——
  2026-10-13 Boss 那 18 条里的 仓库管理员 / 新仓急招小班长 / 打印机维修 就是这样，一条条删要删
  三次。所以另有一张 `blocked_rules` 表按**公司**或**标题关键词**整类拦：
  `python cli.py blocked --keyword 仓库 普工`、`--company 某某公司`，`--drop 关键词:仓库` 放掉。
  判定在 `save_jobs` 里，和单条名单同一层，**命中就不写库、也不刷新已有那条**，回执和
  `collect_runs` 里单独记成"规则拦掉 N 条"。两个口径要记住：**公司整串相等才算**
  （`某某科技` 不会顺手挡掉 `某某科技有限公司`，那是两家公司），**关键词是标题子串、不分大小写**。
  规则只管**以后**采到的，库里已经躺着的那几条不会因为它消失——那些照旧在页面上删。
- 兜不住的量：一次最多 `DELETE_MAX`=500 条，回收站只留最近 `TRASH_KEEP`=20 批
  （免得悄悄攒出第二个库）。想整库清零，直接删 `data/jobs.db` 文件即可。

给页面用的接口（同样带 `X-Token`）：

| 用途 | 接口 |
|---|---|
| 删掉这几条（请求体只有行号，行数据由服务端自己读） | `POST /api/delete` `{"ids":[1,2,3]}` |
| 撤销某一批 | `POST /api/restore` `{"batch":"20261011-225033-82bc3c.json"}` |
| 看回收站里现有哪些批 | `GET /api/trash` |

浏览器只交回行号，不交回职位内容——免得那个令牌变成任意写入的通道。批次号也过了
`BATCH_RE` 严格校验，`../` 之类拼不出别的目录。

两点得说清楚：

- **别把删除当"重置每日额度"的开关。** 剩余条数是按库里今天采集的行数算的，删掉今天采的
  确实会腾出 `DAILY_CAP` 的名额，但那是绕开限速的口子，不是这个功能的目的。
- **`--host 0.0.0.0` 时这个口子也一起开放给局域网**，务必配固定 `JOBSTATS_TOKEN`；
  不想要它就保持默认的 `127.0.0.1`。


## 第二天重采同一个关键词会发生什么

定时跑起来以后，同一个关键词每天都会采到同一批职位。判据是 `平台 + 平台职位编号`
（`jobs` 上那个 UNIQUE 索引），**已见过的不插新行，改走更新**：

| 字段 | 重采时 | 为什么 |
|---|---|---|
| 薪资 / 城市 / 区县 / 经验 / 学历 / 行业 / 规模 / 链接 / 技能 / 福利 | 更新成这次的值 | 涨薪、换城市这些就是要看得见 |
| 这次**空着**的字段 | 保住上次的值（`COALESCE`） | 平台某一页少给一个字段很常见，不该把库清空 |
| `fetched_at`（首次采集） | **不动** | 它是每日 200 条额度的计数依据；重采只算刷新，不占新额度，所以定时跑同一批关键词不会把额度吃光 |
| `last_seen_at`（最近见到） | 更新成这次 | "最后一次见到它还在招"，见下节 |
| `status` / `note`（你的标注） | **不可能被动** | 采集器交不出这两个字段——白名单 `ALLOWED_FIELDS` 里没有，入库前就拦掉了 |

`job51` / `zhitong` 是**每翻完一页就落一次库**（采集器上的 `PER_PAGE_SAVE` 标记），不是等
5 页全采完才一次性写。所以第 3 页撞上滑块验证、`Page.goto` 超时、或者你关了浏览器，
前两页的职位已经在库里了；每日额度也按已落库的条数算，不会一页多塞。Boss 那条通道还是
旧的"整轮采完再存"（那个文件有未提交改动，不做无关改动）。

终端和 `data/logs/collect-YYYY-MM-DD.log` 里那行汇总就是这几类的区分：

```
完成：采到 35 条，入库新增 7 条、刷新 28 条
```

### 「还在招吗」——这是推断，不是平台给的

平台不会告诉你某条职位下架了，库里只有"最后一次采到它是什么时候"这个间接证据。所以筛选台
把原来那一列改名 **首次采集**，旁边加了 **最近见到**；超过 `STALE_AFTER_DAYS`=14 天没再采到的
标成橙色 `⚠`，悬停写明"这是我推断的，不是平台给的状态"。筛选条上多了 **还在招吗**
（全部 / 最近 14 天见过的 / 疑似已下架），排序多了 **最近还见到的**，CSV 导出多了 `最近见到` 列。

- 一条职位被判"疑似已下架"，也可能只是**那几天没跑到它对应的关键词**——比如你后来不再搜
  `python爬虫` 了。所以这一列用来"把长期不更新的分出去看"，别当删除依据。
- 口径想调就改 `config.py` 的 `STALE_AFTER_DAYS`（默认 14 是按"每天定时跑 1~2 个关键词"来的）。
  设成 0 等于把所有老数据都标灰。老库里 `last_seen_at` 为空的历史行，`init_db` 会用
  `fetched_at` 补上，不会出现"从来没见过"的空档。
- 这两列在页面上**只显示到日**，完整时刻（带时分秒）放在悬停提示里。14 列一起排时，
  带上时分秒会在 1100px 宽的窗口里横向溢出，日期还会从中间断成两行。
- 2026-10-14 在真实库上跑过：349 条里 **181 条** 超过 14 天没再采到——全是 09-16 ~ 09-26
  那几批（`IT` 口径的噪音占大头）。剩下 168 条还"见得到"，其中 111 条来自 10-12 / 10-13 两批。


## 各平台说明

| 平台 | 方式 | 登录 | 成熟度 |
|---|---|---|---|
| Boss直聘 | 同源直连 `wapi/zpgeek/search/joblist.json` | 需要（走真实 Edge，见下） | ⚠️ 通道可用，容易触发风控 |
| 前程无忧 | we.51job.com 卡片 sensorsdata 解析 | 不需要 | ✅ 已实测，**日常主力** |
| 智通直聘 | 搜索页服务端渲染 HTML，直连解析条目 `data-*` 字段 | 不需要 | ✅ 已实测，**连浏览器都不用开** |

**智通直聘（2026-09-23 实测）**：`/s/search/?keyword=&city=&pn=` 返回的就是渲染好的 HTML，每条职位是
`<li class="position pos-item PosName" data-...>`，标题/公司/薪资/镇区/学历/经验/福利全在 `data-*` 属性里，
所以用最普通的 HTTP 请求就能采，不用登录也不用开浏览器（实测 30 条/页，镇区与公司零缺失）。
站点前面有道 WAF 会先发 `CT6T` cookie 再 302 一次，带 cookie jar 自动重跟即可。翻页参数是 `pn`
（第 2 页与第 1 页 0 重复）。旧实现之所以"实验性"，是因为它选了 `.job-card`——那是**首页**卡片的类名前缀，
结果页用的是 `pos-item`，所以永远选空。

两条 2026-10-18 的补充：

- **列表页没有技能这一列**。条目下方那串 `tag-list-item` 实测只有六类
  （`城市-镇区 / 学历 / 经验 / 公司性质 / 公司规模 / 行业`），所以智通行的 `skills` 一直为空是
  平台不提供，不是解析失败——技能词要从详情页的 `keyword_tags` 兜底，见下面『技能列的两个来源』。
- **`company_scale` 现在会填了**。以前这一列在智通采集器里写死空串，规模和公司性质其实就混在那
  六类标签里；`_scale()` 取第一个像规模的。重采 2 页实际拿到的是
  `1-100人`/`100-200人`/`200-500人`/`500-1000人`/`1000-2000人`/`2000以上人` 这六种
  （智通写的是 `…以上人`，不是 `…人以上`）。历史行要重采才补上，
  2026-10-18 重采 2 页碰到 36 条，库里 239 条智通行就有 36 条有值。

**Boss直聘 为什么单独一套流程（2026-09-19 实测）**：Playwright 自建的浏览器能打开 zhipin.com，
但十几秒后会被平台的安全脚本清成 `about:blank`；去掉自动化标记、换 Edge 二进制、独立用户目录都躲不掉。
改成**用本机真实 Edge 打开页面、事后用 CDP 接管**（`--edge`），实测接管后页面不再被清空。

```bash
python cli.py login boss --edge     # 或者直接双击项目根目录的 login-boss.bat，是同一件事
```

`login-boss.bat` 就是 start.bat 那套：自己 `cd` 到工程目录、优先用 `.venv` 里的 Python
（**必须用 `.venv`**，playwright 只装在那儿，系统 Python 会直接 import 失败），然后把
登录窗口弹出来。它在命令行之间插了一句提示，剩下的还是你自己扫码、回黑窗口按回车。

登录凭证**默认不放在项目里**，而是和项目外的 Edge 配置目录并排：

```
%LOCALAPPDATA%\job-stats\auth\boss_storage.json     ← 登录态在这儿
%LOCALAPPDATA%\job-stats\edge-profile\              ← 浏览器配置（同样有 cookie）
```

想换成别的文件夹就设 `JOBSTATS_AUTH_DIR`（不设就用上面那个默认地址）：

```cmd
setx JOBSTATS_AUTH_DIR "D:\secrets\jobstats-auth"
```

用 `setx` 设成**用户变量**，别只在某个 bat 里 `set`——采集和 `serve` 也要读同一个位置，
两个命令指向两个目录就等于白扫一次码。改完要重开终端才生效；`login` 那一步会把
实际使用的完整路径打印出来，扫之前先确认一眼。这个目录等于你的招聘账号凭证：
**别设到网盘/同步目录或网络盘上**，同步一份就等于多台机器能登你的号。
默认放在项目外之后，整个 `job-stats\` 文件夹随时可以压缩、拷走、发人，不会夹带登录态。

登录判据是 cookie 里的 `bst` / `zp_at`（匿名访问只有 `__a`/`__c`/`__g` 之类），检查用的是浏览器级
API，不依赖任何标签页——Boss 的 SPA 跳转会把接管的标签页换掉，靠 Page 对象会崩。
采集同样不开页面、不监听响应（响应体在 CDP 下经常取不到），而是用同一个登录上下文
直接 `ctx.request.get` 调搜索接口翻页。

**那个 Edge 窗口不用你管**（`boss.ensure_window()`）：命令行 `collect` 和页面上的『开始采集』都会先
经过它——窗口不在就自己重新弹出来（profile 里已有 cookie，不用再扫码），只有**从没登录过**时才弹
登录页并提示"扫完码再点一次开始采集"。不会再偷偷退回自建浏览器——那条死路只会换回一个
`code=37`，还让人误判成"风控了"。

**每次翻页都重新接管一次 Edge**（`boss.Channel`）。CDP 连接随时会没：窗口被关、被别的 Edge 实例接管、
Edge 自己更新，都会让长期持有的请求上下文变成 `Request context disposed`，一整轮采集跟着报废。
现在断了只重试当前那一页，连续两次接不上才放弃。放弃时只打印报错的**第一行**——Playwright 的
`Call log` 会把请求头原样带出来，里面就有 `bst` / `zp_at` 这两个登录凭证，绝不能落到终端上。
（如果你之前看到过带 cookie 的 traceback，那串凭证当时是明文显示在窗口里的，别把那种日志外发。）

重试时如果发现**窗口整个不在了**（`browser.attach()`），会先自己把窗口弹回来一次再接着跑：
中途被随手关掉是常态，不该算风控、也不该叫你回去敲 `login`。真的弹不回来才报错，
话里给的是那条备用命令。

这条通道专用的浏览器配置刻意放在项目外：`%LOCALAPPDATA%\job-stats\edge-profile`。
Edge 会往任何用户目录里塞自带组件和缓存（实测 100M+），放项目外免得拖大工程体积；
登录状态在里面，勿外传。

**风控实测**：Edge 通道下单页请求正常返回 15 条；连续多页/短时间内反复请求会返回
`code=37 您的环境存在异常`。遇到就停手，隔天再跑，一次一页足够。

`code=37` 有两个来源，别混成一个：**翻太快**（上面那种，停手就行）和**登录态过期**
（重启命令也没用，只能重新扫码）。后者不用再靠猜——`python cli.py status` 直接把
`bst` / `zp_at` 还剩几天打出来。2026-10-12 实测那份 09-26 登录留下的
`boss_storage.json`，`bst`/`zp_at`/`wbg`/`wt2` 都过期 8.8 天、`__zp_stoken__` 过期 13.5 天，
采集就是一整条 `code=37` 加"一条都没采到"。检查只看 cookie 的名字和有效期，
值不会往终端上打（`status` 里也打不出值）。

## 口径统一（技能/福利/经验/学历）

三家平台往"技能"这一列塞的东西完全不一样，直接合并统计会得出"第一名是五险一金"这种结论：
智联基本只给福利、前程无忧的标签其实是福利、Boss 连学历（大专/本科）和年限（3-5年）都往里放。

`jobstats/skills.py` 在**读取侧**统一一次：大小写与别名归一（`python`/`PYTHON` → `Python`、
`英文` → `英语`）、同义福利合并（`年终奖`/`年终奖金`、`团建聚餐`/`定期团建`、五险的五个险种
→ `五险`）、混进技能列的福利词挪回福利列、与 `education`/`experience` 重复的标签丢掉。

入库存的仍是平台原文，所以**改规则不用重采**——历史数据下次读出来就跟着变。
要加别名就往 `ALIASES` / `WELFARE_ALIASES` 里补一行。

### 技能列的两个来源（"没词"不等于"没要求"）

2026-10-20 在真实库 409 行上数的"技能"这一列：

| 平台 | 行数 | 词来自列表页标签 | 来自详情页关键词（兜底） | 两处都没有 |
|---|---|---|---|---|
| 智通直聘 | 239 | **0** | 22 | 217 |
| 前程无忧 | 112 | 104 | 0 | 8 |
| Boss直聘 | 58 | 30 | 0 | 28 |

智通那 239 行在**库里** `skills` 全是空的，这不是解析失败，是它的列表页压根没有技能这一列
（那六类标签的清单见上面『各平台说明』智通那条）。技能词写在详情页的
`<ul class="keyword-tags">` 里，抓过正文才拿得到——而正文有每日 20 条的额度，
所以兜底只覆盖到 22 条，不是 239 条。

`db.fetch_all()` 因此在读取侧做了两件事（库里一个字没改）：

- **兜底**：这一行 `jobs.skills` 清洗后为空、而它在 `job_details` 里有 `keyword_tags`，就用关键词
  顶上，并给这行标 `skill_src = 'jd'`；页面在技能格下方挂一个黄色『来自详情页』小标签。
  来源不一样要说出来：详情页关键词是 HR 自己填的，比列表页那列松，混在一列里统计会偏。
- **把"没有"说清楚**：`skills.NO_LIST_SKILLS`（平台 → 一句原因）喂给界面和报告。这一列空、
  且平台在这张表里，页面显示灰色的"没采到技能"（悬停是那句原因），**不显示光秃秃的 `—`**——
  后者会被读成"这个职位没写技能要求"，而事实是"这个平台的列表页不提供技能"。
  前程无忧/Boss 不在表里（它们的列表页确实有这一列，同一列里别的行有词就是证明），
  那 8+28 条空仍是 `—`，是真的这条没填。

统计行同理：技能计数分开报"来自列表页 / 来自详情页 / 两处都没取到"，末尾一句"没词不等于没要求"；
静态报告的『技能需求 Top』下方同一句说明（`_skill_caption()`）。
以后再有平台列表页不给技能列，就往 `skills.NO_LIST_SKILLS` 里补一行原因，界面不用改。

### 经验/学历：47 种写法收进 7 档

同一个要求，三家平台各写各的（多半是各自加了个"经验"前缀）。2026-10-14 数了一下真实库：
`experience` 有 **47 种**写法——`经验经验不限`(61 条)、`经验不限`(4)、`无需经验`(10) 是同一件事，
`3年及以上`(33) 和 `经验3年及以上`(26) 也是；`education` 10 种（`中专`/`中专/中技`/`中技/中专`）。
全列成筛选项就没人会用，所以 `skills.exp_bucket()` / `edu_bucket()` 在读取侧归档，
规则是**只看区间下限**（能不能投取决于门槛，上限不参与）：

| 经验档 | 合并了哪些原文（举例） | 库里条数 |
|---|---|---|
| 经验不限 | `经验不限`、`经验经验不限`、`无需经验` | 75 |
| 应届/在校 | `在校/应届`、`应届毕业生-2年`、`在读学生-应届毕业生` | 13 |
| 1年以内 | `1年以内`（"以内/以下"是上限说法，跟 `1年及以上` 不同档） | 2 |
| 1-3年 | `1年及以上`、`经验2-10年`、`1-2年` | 93 |
| 3-5年 | `3-5年`、`3年及以上`、`经验3-10年` | 116 |
| 5-10年 | `5-10年`、`经验5-8年`、`经验8年及以上` | 49 |
| 10年以上 | `10年以上` | 1 |

学历 6 档：`学历不限` / `初中及以下` / `高中/中专` / `大专` / `本科` / `硕士及以上`
（`硕士`/`研究生`/`博士` 合成一档）。读不出数字也没有关键词的进 `其他`，平台那栏本来就空的是
`未标注`——**没有一种原文会被悄悄丢掉**，归不进去的就摆在 `其他` 里提醒你规则该补了。
要调档序或门槛就改 `skills.py` 的 `EXP_BUCKETS` / `_exp_band()`，同样不用重采。

界面上：那两行 chip 从 47/10 个变成 7/7 个（窗口宽 ≥ ~900px 就一行放得下，窄了会折成两行），
chip **仍然多选**（本科+大专一起看很常用），悬停写明这一档合并了哪些平台原文和条数；
表格里 经验/学历 两列显示档位、悬停看原文；统计报告那两张饼图同口径（不然 47 个扇区）。
**`data/jobs.db` 和导出 CSV 里存的仍是平台原文**，一个字符都没改。

**登录凭证不在这个树里**：默认在项目外的 `%LOCALAPPDATA%\job-stats\auth`（和 Boss 专用的
`edge-profile` 并排，两处都有 cookie）。`JOBSTATS_AUTH_DIR` 可以换成别的文件夹，但别放同步盘。
所以这个工程文件夹本身任何时候都能压缩发人。

`serve` 默认只绑定 `127.0.0.1`，页面接口带 token（不设 `JOBSTATS_TOKEN` 时每次启动重新生成），
用于挡住本机其它进程/网页的跨站请求；采集接口会真实驱动浏览器，不要转发或反代该端口。
要接本机 Docker 里的 n8n 才需要 `--host 0.0.0.0` + 固定 `JOBSTATS_TOKEN`，
详见上面『匹配度分析』一节——那等于把服务开放给整个网段，别只改地址不设令牌。

Boss 的 Edge 通道同理只监听 `127.0.0.1:9223`，那是那个窗口的调试端口，本机任何进程都能驱动它——
用完关掉窗口即可，同样不要转发或反代。

## 测试

```bash
python -m unittest discover -s tests        # 核心层：薪资解析/入库去重/额度/HTML 输出加固/分析回写/删除与撤销/相关性闸门（词元·职类·蓝岗词表）/登录态体检/任务日志落盘/跨平台对照归一/技能列来源兜底/纯文本摘要 digest/服务启停日志与端口锁
```

309 个用例，本机实测 13.7 秒跑完，全程不联网、不开浏览器（采集器的诊断分支是喂构造好的 HTML 测的）。
上一批新增的覆盖面：重采只刷新不插新行、空字段不覆盖旧值、重采不占每日额度、`status/note`
不会被采集冲掉、老库补 `last_seen_at`、每页落库（第 3 页抛异常时前两页已在库里）、
屏蔽名单拦住下次采集 / 撤销时放掉 / `--clear boss:*` 按平台放掉。
再上一批：正文批次不再被一条死通道拖垮、登录态闸门的判据换成实时通道（快照文件过期不算）、
Edge 窗口起不来只废 Boss 那几条、`digest` 的天数不把补不了的算进去、`--ids` 空值不再掉进自动补抓。
**所有碰登录态的用例都必须同时 patch `browser.cdp_alive` 和 `browser.attach`**——只 patch
`AUTH_DIR` 的话，跑巡检的人当天开着 Edge 就会读到真凭证，测试结果跟着环境变（这条踩过一次）。
这一批：库里那 47 种经验原文逐个归档（必须落进 7 档、一个都不掉进 `其他`）、下限规则
（`1年以内` ≠ `1年及以上`、`10年以上` 不算上限）、`fetch_all` 带出档位而原文不变、
CSV 表头仍是那 22 列原文、两张饼图按档位计数、表格里档位与表头列数对齐。
再一批：正文能力表——前程无忧的行不占 `--limit` 名额也不动今日额度、接口回的是那句原因
而不是"职位可能已下架"、页面按钮按平台改文案（不抓正文的那版不发请求）、
`待补正文` 的口径把它们摘出去、新增平台必须在"能抓正文"和"说明为什么不能"里二选一。
最新一批：跨平台对照——公司名连着两个后缀要剥两轮才对得上、同平台出现两次不算"别处也有"、
归一后公司名或标题为空的那条不参与对照、对面那条有没有正文一起带出来、
标签只在真的出现 ≥2 个平台的组里出现，以及面板展开后表列数仍是 14。
再新一批：技能列来源——列表页有词时不许正文盖上来、只有正文没列表词才兜底、
福利词从详情页关键词里照样挪出去、没有正文的行不凭空造词、老库没有 `job_details` 表也照样读、
`NO_LIST_SKILLS` 里的平台必须是真通道且原因非空、统计说明把两个来源分开计数，
以及一条**防整个页面失效**的守卫：模板字符串里的 JS 单引号必须成对（Python 会把 `'\n'` 吃掉变成
真换行，整段 `<script>` 语法错，页面所有控件一起死掉——上一轮就是这么翻的车，现在测试盯着）。
还有一条免费的：智通列表标签里的公司规模解析进 `company_scale`（以前恒为空串）。
巡检这批：`pending_analysis`（喂模型那条读取口）和 `fetch_all`（页面/CSV 那个口）必须给出同一份
技能——分叉过一次，页面上写着 14 个技能词的职位，提示词里回的是「技能标签：未列」，
模型照着"这条没写技能"打分；现在两个口共用 `db._clean_row_skills()`，测试盯着这条。
接影刀那批：巡检只在那段中文里匹配判据，所以 `TestLoginStateReport` 里加了两条契约用例——
登录态健康时那四个负面词（`已过期`/`还没保存过登录态`/`判据缺失`/`看不出有效期`）一个都不许出现
（出现了就是天天误报），四种坏状态各必须命中至少一个（漏掉哪种就是那种情况下它一声不响）。
`login-check.bat` 本身不判断，它只负责把 `status boss` 落成 UTF-8 文件——编码是那条链路唯一
真正容易翻车的地方。
`digest` 那批钉的是**给邮件用的形状**：重采只算一次新增、没新增的那天也要出现在近 N 天里
（补零，不然邮件上看不出"今天真的没有"）、今日零新增时不许冒出"今日分平台"那行、
一条分数都没有时只许说"还没跑过分析"不许列职位、有分数时最多三条且按高到低、
`88.0` 要写成 `88`（库里存一位小数，邮件里拖个 `.0` 像是坏了）、`--days` 给多大都只到 30、
老库里没建 `job_details`/`job_analysis` 时它自己把表补上（不然摘要那个位置回一句
`OperationalError: no such table`，而外部程序只会把这句话当正文发出去）。
2026-10-22 把整个项目挨个跑了一遍，那批钉的全是"看着跑成功了其实没干活"的那类：
`detail --ids ""` 不许再被当成"没给参数"掉进自动补抓（实测真把一天 20 条正文额度静默花光）、
`--ids 562,56a` 给一句中文而不是 `ValueError` 堆栈、行号一个都对不上时不许说成"都已抓过"；
重定向出去的 stdout 必须是 UTF-8 且吃得下非 GBK 字符（标题里一个 🔥 就能打断整条摘要），
而测试里那种没有 `reconfigure` 的 stdout 也不许炸；
GET/POST 路由里冒出来的异常必须变成带原因的 500（"Failed to fetch" 是把本地服务的错
推到网络上），连接先断了就闭嘴别再发响应；`fetch_all` 按 `salary_raw` 兜薪资区间
但**不许写回库**，`面议` 照旧留空；直方图最后一档开口，柱子加起来必须等于有区间行数；
中位数两端同一条规则（4 条 10/12/14/100：报告和页面都给 13.0，旧 JS 给 14.0）；
回收站写完不许留 `.tmp`，且那一批必须还能被"撤销"读出来；
两条浏览器通道都起不来时必须 `stop` 掉 driver，退回内置 Chromium 成功时不许 stop。
2026-10-23 这批钉的是"报了成功、其实是空的/反的"：自述文件里还有 `【…】` 时 `analyze` 必须停下
并且给一句 `--dry-run` 的出路（`status` 也不许说"已就绪"，得报出还剩几处、例如哪一个），
而 `--dry-run` 是纯预览，占位没填也照样让看；撤销回来的行必须把 `last_seen_at` 原样带回
（少了这一列，页面 `seenAt` 退回第一次采到的日子，在职职位会被标成「疑似已下架」）；
`report.html` 在图表库加载不到时不许留八块空白，而且那句提示必须排在第一次调用 `echarts` 之前
（否则 ReferenceError 先把整段 script 打断），模板里花括号还得配平——少闭一个 `}` 的现场
就是"页面照开、图全没了"。
2026-10-24 查日志那批钉的是服务自己：`serve` 的启停必须落到 `serve-YYYY-MM-DD.log`（启动那行带 pid、
监听地址、令牌是固定还是随机、当日额度用了多少），抢不到端口锁的那次也要留一行；令牌**值**本身不许进日志；
锁文件所在目录开不了时服务照常起（宁可少一道拦，也别把服务挡在门外）；`停止：…` 只有正常收尾才写，
所以用例是把 `serve_forever` 换成抛 `KeyboardInterrupt` 走完整收尾。最关键那条是端口锁本身：
`ThreadingHTTPServer` 必须**一次都没被调用**——拦在 bind 之前才算拦住了，撞完端口再报错就晚了。

## 修改界面

筛选台的 HTML/JS 只有一处：`jobstats/report.py` 的 `FILTER_TEMPLATE`。

## 统计维度

薪资分布直方图、各平台职位量与薪资中位数对比、城市 Top、技能需求 Top（下面一行写清词来自
列表页还是详情页，见『技能列的两个来源』）、
学历/经验分布（按上节归档后的档位，不是平台原文）、福利标签、最近职位明细表。
直方图最后一档是 `100k以上`，不设上限：有上限的话一条 12 万的岗位哪个档都不落，
柱子加起来比总数小，看着像"高薪岗位更少"。
中位数两边同一条规则：偶数条取中间两个的平均（`statistics.median` 那个），筛选台的
`月薪中位数（K）` 卡片以前取的是上中位，职位数为偶数时和报告能差 1K——那两处是拿来对照的。
